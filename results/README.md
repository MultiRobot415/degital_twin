## 各ランの内容

### `141221_shield_multi` — 複数障害物版・成功
`mode=shield_multi`（全障害物を LSE smooth-min で1本の制約にまとめる）。片道 S→G、96 s。

| | Agent 1 | Agent 2 | Agent 3 |
|---|---|---|---|
| h 最小 | +0.145 | +0.183 | +0.150 |
| `sdf<0` | 0 steps | 0 steps | 0 steps |
| スラック作動 | 243 steps (peak 0.293) | 480 steps (peak 0.086) | 126 steps (peak 0.280) |
| ゴール残差 | 0.161 m | 0.071 m | 0.061 m |

**一度も安全距離を割っていない。** 3機とも障害物を大きく迂回している。

### `143101_shield` — 単体版・成功
`mode=shield`（最近傍1個だけを見る）。片道 S→G、63 s。

| | Agent 1 | Agent 2 | Agent 3 |
|---|---|---|---|
| h 最小 | **+0.001** | +0.164 | +0.065 |
| `sdf<0` | 0 steps | 0 steps | 0 steps |
| スラック作動 | 24 steps | 2 steps | 12 steps |
| ゴール残差 | 0.186 m | 0.091 m | 0.105 m |

違反ゼロだが **Agent 1 の h が t≈28 s で 0.001 まで落ちて安全境界に接触寸前**。
複数版（最小 0.145）と比べて余裕が2桁近く小さい。迂回が浅いので 63 s で終わり、
スラックの作動も少ない。**「速いが余裕を失う」対「遅いが余裕を保つ」のトレードオフ**が
141221 との対比で読める（複数障害物拡張のアブレーションに使える組み合わせ）。

### `142953_shield` — 単体版・往復したが接触寸前
`mode=shield`。**往復 S→G→S**（Bキーで帰還）、88 s。ゴール残差が経路長ぶん（約2 m）
出るのは復路で S に戻っているため。

`sdf<0` の原因を記録値と計算値の突き合わせで特定済み:

| 機体 | 時刻 | sdf | 原因 |
|---|---|---|---|
| Agent 1 | 29.8–31.4 s | −0.029 | 静止障害物 ID4 |
| Agent 1 | 71.3–71.9 s | −0.035 | 壁 x=+1.2（x=1.135） |
| Agent 2 | 67.0–68.0 s | −0.017 | **Agent 3** |
| Agent 3 | 67.5–67.6 s | −0.015 | **Agent 2** |

**Agent 2 と Agent 3 が中心間 0.189 m まで接近**（必要 0.20 m）。Tello はプロペラ込みで
対角 ~0.18 m なので、ほぼプロペラ同士が触れる距離。

原因は **G3 と S2 が同一点**（ROS (−0.7,−0.7)）であること。復路で Agent 3 が G3 に停まった
まま、Agent 2 が S2 へ帰ってくるため構造的に正面で鉢合わせする。**往路では起きず、
Bキーの復路で必ず起きる。** 対策は G3 を S2 から離すこと（例: ROS (−0.7, 0.0) ＝
生mocap (0, −0.7)。S2 から 0.70 m 離れ、機体3が会場を横一直線に横断する形になる）。

### `142733_shield` — 単体版・失敗（参考）
`mode=shield`。Agent 2 の総移動 0.83 m、Agent 3 は 0.57 m で、**この2機はミッションを
飛んでいない**（Agent 1 のみ 6.97 m）。

| 機体 | 時刻 | sdf | 原因 |
|---|---|---|---|
| Agent 1 | 0.5–21.4 s | −0.185 | Agent 2（下記参照） |
| Agent 1 | 32.8–42.6 s | −0.152 | 壁 y=−1.2（y=−1.252） |
| Agent 2 | 0.4–21.8 s | −0.185 | Agent 1（下記参照） |
| Agent 3 | 34.2–84.0 s | −0.073 | 壁 x=+1.2（x=+1.173） |

Agent 1 と Agent 2 の「違反」は**物理的にありえない**。両機とも静止したまま
記録位置が 0.015 m しか離れていない（Tello 1機で対角 ~0.18 m）。mocap が2つのIDに
ほぼ同じ位置を報告していた（剛体の取り違え・重複登録）状態と考えられる。
残る2件はいずれも仮想の壁からの逸脱で、実在の物体との接触ではない。
**このランに機体同士の衝突は記録されていない。**

## 既知の制約

- **npz に高度 z が記録されていない**（`x` は `[px, py]` のみ）。SHIELD は XY 2次元なので
  制御上は不要だが、「高度差があってすれ違っただけ」なのか「本当に同じ高さで接近したか」を
  ログから判定できない。`shield_filter_node.save_record` に追記すれば次回から残せる。
- `obstacles` フィールドは**最終フレームの値のみ**。相手機の位置は動くので、静止障害物
  （配列の末尾2件）以外は時系列として使えない。相手機の軌跡は各機の npz の `x` を使う。
- ゴールに 0.06〜0.19 m の残差が残るのは、トラッキング補正 `u − E[d]` と P制御（積分項なし）
  の釣り合いによる構造的なもの。`0.8·err ≈ |E[d]| ≈ 0.17` の点で停まる。

## npz のフィールド

`t, x[N,2], yaw, u_nom[N,2], u_safe[N,2], h, sdf, alpha, slack, obstacles, wall_bounds,
slack_weight, robot_radius, mode`
